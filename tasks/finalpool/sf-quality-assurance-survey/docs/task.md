Our quality assurance team needs a comprehensive assessment of support ticket handling performance. The first step is to visit our internal quality standards portal at http://localhost:30213 to review the current target metrics for response times, customer satisfaction, and resolution rates. The portal has two pages, the main page showing target numbers and a standards page with best practices details.

After reviewing the quality targets from the portal, pull all support ticket data from our database. We track tickets with fields like priority level, response time, customer satisfaction rating, issue type, and resolution status. The ticket table includes a REPORTER field; in our system the person recorded on each ticket (the REPORTER) is the one who handled it, so the authoritative list of agents to analyze is the set of distinct REPORTER values found in the ticket data. We also maintain a separate agents table and a team roster CSV that list support agents with their team assignments and skill levels; use those only as supplementary context (for example, to source the team options for the form), never to filter the ticket data. Analyze each agent by computing their average response time across all their tickets, their average customer satisfaction score, and their overall resolution rate as a percentage. Compare each agent metric against the portal targets and identify which areas fall below standard for each agent.

Create an Excel workbook called QA_Assessment.xlsx in your workspace. The first sheet should be named "Agent Scorecard" with columns for the agent name, their average response time in hours rounded to two decimal places, their average customer satisfaction rounded to two decimals, their resolution rate as a percentage rounded to one decimal, and a text field listing all the target areas where the agent falls below the published standards (for example "Response Time, Satisfaction" if both are below target). Sort the rows alphabetically by agent name.

The second sheet should be called "Issue Type Analysis" and should break down performance by issue type. Include columns for the issue type name, total ticket count for that type, average response time in hours rounded to two decimals, and average satisfaction score rounded to two decimals. Sort alphabetically by issue type.

The third sheet should be named "Summary" with two columns, Metric and Value. Include the following summary metrics: Total_Tickets (total ticket count across all data), Overall_Avg_Response_Time (the overall average response time rounded to two decimals), Overall_Avg_Satisfaction (overall average satisfaction rounded to two decimals), Overall_Resolution_Rate (overall percentage rounded to one decimal), Agents_Below_Satisfaction_Target (count of agents whose average satisfaction is below the portal target), and Agents_Below_Response_Target (count of agents whose overall average response time exceeds a reasonable benchmark, specifically those above the medium priority response target from the portal).

Also review the QA checklist markdown file provided in your workspace for context on scoring methodology. The team roster CSV lists support agents and their team assignments; note that it is maintained separately from the ticket system and may be out of date, so treat the distinct REPORTER values in the tickets as the authoritative list of agents for the scorecard rather than filtering tickets by the roster names.

Finally, create a Google Form titled "QA Self Assessment Survey" that agents can use to self-evaluate their performance on the identified weak areas. The form should contain five questions, each of which must be one of the two question types the form builder supports: a single-choice multiple choice question, or an open text question. The first question should ask for the agent name as a short open text question and should be required. The second question should ask which team they belong to, as a single-choice multiple choice question with options matching the teams from the agents table, and should be required. The third question should ask them to rate their own response time performance, as a single-choice multiple choice question with exactly the options "Exceeds Target", "Meets Target", "Below Target", and "Needs Improvement", and should be required. The fourth question should ask about their biggest challenge in meeting quality targets, as an open text question, and should be required. The fifth question should ask for suggested improvements to the QA process, as an open text question, and should not be required.

Important: all numeric cell values in QA_Assessment.xlsx must be written as literal numbers (for example 14.94 or 100), not as Excel formulas — the grading system reads the stored cell values directly.
